ClickHouse (DWH)

Описание: Основное аналитическое хранилище (Data Warehouse) системы. Отвечает за хранение больших массивов данных (OLAP), а также используется для векторного поиска.

  • Схема и данные: Хранит 5M+ записей (например, данные по налогам, задолженностям, плательщикам).
  • Векторный поиск: Использует функцию cosineDistance для поиска похожих документов и контекста напрямую из SQL.
  • Связи: Взаимодействует с DataAgent, который генерирует SELECT запросы, и с ETL / Airflow DAG, который загружает в него данные из PostgreSQL.
  • Безопасность: Все запросы фильтруются через RLS (Row-Level Security), физически модифицируясь (например, WHERE region='г.Гродно') перед отправкой в БД.

Глубокий разбор каждого узла

🗂️ search_node

Слой мгновенного ответа. Маршрутизатор кэша.

  • Используемые агенты: Нет (LLM не вызывается).
  • Что делает: Проверяет Semantic Cache. Если ответ на похожий вопрос уже был сгенерирован, мгновенно возвращает его, экономя ресурсы.
  • Bypass: При drill-down (проваливании в данные графика) кэш принудительно игнорируется.

🧠 planner_node

Слой бизнес-понимания и подготовки контекста.

  • RagAgent: Ищет в ChromaDB бизнес-контекст, глоссарий терминов и релевантные схемы ClickHouse.
  • TaskDecompositionAgent: Если запрос юзера сложный, этот агент разбивает его на список атомарных подзадач, формируя план.

🚦 supervisor_node

Главный маршрутизатор (LLM Router).

  • Используемые агенты: Легкий вызов LLM (роутер).
  • Что делает: Оценивает, требуют ли подзадачи обращения к базе данных (ClickHouse). Возвращает направление маршрута: data (нужен SQL) или direct_answer.

💾 data_node (Ядро)

Text-to-SQL движок и выполнение запросов.

  • DataAgent: Пишет SELECT запросы к ClickHouse. Обладает правом на 3 попытки самоисправления при синтаксической ошибке.
  • SqlEvaluatorAgent: Выступает в роли LLM-as-a-Judge. Проверяет сгенерированный SQL на логическую корректность до его реального выполнения.

📊 analyst_node

Математика + ИИ-нарратив.

  • Алгоритмы: Детерминированный скрипт вычисляет Z-Score для поиска аномалий (outliers) в сырых данных без участия LLM.
  • AnalystAgent: Формирует связный рассказ (3-4 ключевых инсайта, объясняющих цифры) и предлагает пользователю follow-up вопросы.

🧐 reviewer_node (CDO)

Независимый контроль качества.

  • ReviewerAgent: Роль Chief Data Officer. Проверяет текст аналитика на наличие "галлюцинаций" (сравнивает текст с фактическими цифрами из SQL ответа).
  • Что делает: Если находит ошибку, отправляет is_good=False с критикой, возвращая графовый поток обратно в analyst_node (цикл саморефлексии ограничен 1 повтором).

🎨 presenter_node

Сборка финального UI-компонента.

  • ChartAgent: Выбирает оптимальный тип графика (line, bar, pie) на основе эвристик. Вызывается другими агентами.
  • DashboardAgent: Компонует KPI-карточки и графики в единую структуру дашборда.
  • PresentationAgent: Разбивает данные на слайды и генерирует бизнес-презентацию.
  • ForecastAgent: Если запрошен прогноз, применяет модели прогнозирования временных рядов.

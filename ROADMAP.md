# Roadmap: Enterprise Features (Фаза 23+)

Данный документ содержит детализированный план развития аналитической платформы. Эти функции были отложены на следующие итерации, но именно они превратят систему из прототипа в полноценный Enterprise AI-продукт.

---

## 1. Self-Healing RAG (Самообучающаяся память)

**Проблема:** Сейчас RAG ищет только по схеме данных (`semantic_model.yaml`), и если модель один раз ошиблась в генерации сложного SQL, она может ошибиться снова.
**Решение:** 
Создание механизма обратной связи. Когда сгенерированный SQL успешно выполняется и получает одобрение `ReviewerAgent` (или самого пользователя), пара `(Вопрос пользователя, Успешный SQL)` сохраняется в векторную базу данных ClickHouse. 
**Архитектура:**
- При новом запросе RAG делает поиск не только по `semantic_model`, но и по коллекции `successful_queries`.
- Если находится совпадение (cosine similarity > 0.85), RAG подмешивает этот успешный SQL в промпт для `DataAgent` как **Few-Shot пример**.
**Бизнес-ценность:** Система будет "умнеть" каждый день без вмешательства разработчиков. Сложные уникальные вопросы, отвеченные один раз, навсегда остаются в "мышечной памяти" системы.

## 2. AI ETL Wizard (Магический импорт сырых данных)

**Проблема:** Интеграция новых источников данных (например, Excel отчетов из региональных отделений) требует работы дата-инженера для написания скриптов загрузки в ClickHouse.
**Решение:**
Автоматический конвейер загрузки данных прямо через интерфейс чата. 
**Архитектура:**
1. Пользователь загружает `.csv` или `.xlsx` в чат.
2. `ETLAgent` читает первые 100 строк (с помощью Pandas/Polars), определяет типы колонок (int, float, date, text).
3. Агент генерирует DDL `CREATE TABLE` для ClickHouse и выполняет его.
4. Данные загружаются через `clickhouse-connect`.
5. Агент **автоматически модифицирует** `semantic_model.yaml`, добавляя описание новых метрик.
**Бизнес-ценность:** Time-to-market для новых данных сокращается с дней до минут. Бизнес-пользователи могут сами загружать и анализировать свои локальные данные.

## 3. Data Lineage (Доверие к происхождению данных)

**Проблема:** Руководители часто сомневаются в цифрах: "Откуда взялась эта сумма? Какие фильтры применены?"
**Решение:**
Визуализация происхождения каждой цифры под графиком.
**Архитектура:**
- Разработка нового UI-компонента в React (`LineageGraph.tsx`).
- Модификация `DataAgent`: при возврате данных агент также возвращает AST-дерево разбора SQL (используя библиотеку `sqlglot`).
- Пользователь кликает "Как это посчитано?", и видит визуальный граф: `[Сырая таблица: tax_data] → [Фильтр: region='Минск'] → [Агрегация: SUM(accrued)] → [Результат]`.
**Бизнес-ценность:** Абсолютная прозрачность вычислений и рост доверия топ-менеджмента к AI-отчетам.

---

## 4. Advanced ML Forecasting & "What-If" Анализ

**Проблема:** Классическая аналитика смотрит в прошлое. Бизнесу нужно смотреть в будущее и моделировать сценарии.
**Решение:**
Внедрение предиктивных ML-моделей прямо в базу данных и симуляторов на фронтенд.
**Архитектура:**
- Подключение библиотек `Prophet` или `ARIMA` в Python backend.
- "Режим симуляции" на фронтенде: ползунки для изменения переменных (например, рост ВВП, изменение ставки налога).
- Бэкенд пересчитывает прогнозные значения с учетом новых весов и отдает обновленные данные для графика.
**Бизнес-ценность:** Мощный инструмент для стратегического планирования бюджетов и оценки рисков.

---

## 5. Долгосрочная память (Long-Term Memory)

**Проблема:** ИИ каждый раз начинает диалог "с чистого листа" и не знает контекста предыдущих сессий или должности пользователя.
**Решение:**
Глобальная память о пользователе с использованием графовой БД или ChromaDB.
**Архитектура:**
- Сохранение `User Profile`: любимые типы графиков (например, "Иван всегда просит bar charts"), часто анализируемые регионы.
- Агент `ContextRetrievalNode` перед ответом подтягивает этот профиль в системный промпт.
**Бизнес-ценность:** Премиальный пользовательский опыт (Hyper-personalization) — ИИ понимает пользователя с полуслова.

---

## 6. Vision PDF & Голосовой интерфейс
**Проблема:** Руководителям за рулем неудобно печатать. Много исторических данных хранится в PDF-отчетах в виде сканов.
**Решение:**
- Интеграция `Whisper` от OpenAI (или локального аналога) для преобразования голоса в текст в реальном времени.
- Интеграция `Qwen-VL` или `LLaVA` для того, чтобы пользователь мог прикрепить картинку со старым графиком и сказать "Сравни эти показатели с данными за этот год".
**Бизнес-ценность:** Радикальное расширение способов взаимодействия с системой (Omnichannel AI BI).

## 7. Архитектурные обновления (на основе референсов)

**Продвинутый Semantic Layer (MDL):**
Внедрение строгих связей (Relationships) и вычисляемых метрик (Measures) в семантическую модель (`semantic_model.yaml`), чтобы исключить ошибки ИИ при JOIN'ах и математике.

**Step-by-Step генерация (Intent -> SQL):**
Разделение пайплайна генерации SQL на два этапа: сначала определение намерений (выбор нужных таблиц и колонок), затем генерация самого запроса.

**Система памяти (Memory System):**
Внедрение продвинутой архитектуры памяти (Short-term, Long-term, Entity memory) для персонализации и сохранения контекста между запросами (расширение пункта 5).

**Асинхронное делегирование (Delegation):**
Переход от жесткого LangGraph к динамическому делегированию задач. Агенты смогут перепоручать задачи друг другу асинхронно для исправления ошибок.

**IDK Dataset (I Don't Know):**
Механизм защиты от галлюцинаций. Интеграция примеров нерешаемых вопросов, чтобы ИИ честно отказывался отвечать при отсутствии данных в БД.

**Hybrid Search (Векторный поиск + Текст):**
Реализация гибридного RAG. Комбинирование векторного поиска (`cosineDistance`) с классическим полнотекстовым поиском внутри ClickHouse для максимальной точности.

**AggregatingMergeTree для мгновенных Дашбордов:**
Использование специальных агрегирующих движков таблиц ClickHouse для предрасчета тяжелых агрегаций. Позволит дашбордам загружаться за миллисекунды.

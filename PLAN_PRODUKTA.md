## A.1. Данные и структуры БД (критично)

| # | Что запросить | Формат | Зачем нам | Куда в проекте |
|---|---------------|--------|-----------|----------------|
| 1 | **ERD / схема связей** (таблицы, FK, cardinality) | PDF/draw.io + DDL | Planner и DataAgent должны знать JOIN, а не одну таблицу | `domain/semantic_model.yaml`, промпты DataAgent |
| 2 | **DDL** всех таблиц fact/dimension | `.sql` | Whitelist колонок, валидация SQL | `domain/constants.py` → динамический schema registry |
| 3 | **Словарь данных** (глоссарий) | Excel/Confluence: колонка → бизнес-имя → описание → единица | RU-подписи, action_title, инсайты без жаргона | `domain/metrics_catalog.yaml`, `viz/style.py` labels |
| 4 | **Каталог метрик** | «Выручка = SUM(...) WHERE ...», grain, периодичность | Text-to-SQL без логических ошибок | `domain/metrics_catalog.yaml`, few-shot SQL |
| 5 | **Примеры 10–20 «эталонных» SQL** | Рабочие запросы аналитиков | Few-shot для DataAgent под реальную схему | `app/agents/data_agent.py` или внешний `prompts/sql_few_shot.yaml` |
| 6 | **Объёмы и SLA данных** | строки/таблица, частота обновления, задержка ETL | LIMIT, кэш, таймауты, материализованные витрины | `app/config.py`, DataAgent, Job API |
| 7 | **Тестовый дамп / sandbox** | anonymized CSV/Parquet или read-only DB | Регрессионные тесты, live eval | `data/` или отдельный `data/sandbox/` |
| 8 | **Политики доступа к данным** | кто какие таблицы/регионы видит | Row-level security, фильтры UI | Orchestrator + DataAgent + auth |
| 9 | **Запрещённые операции** | нельзя PII, нельзя cross-dept | SQL sandbox | DataAgent guardrails |
| 10 | **Именование периодов** | `2024-Q3`, `2024-01`, fiscal year | Правила фильтра по дате (как сейчас `period LIKE`) | domain rules в промпте |

**Минимум для старта пилота:** пункты 1–5 + 7.  
**Без словаря метрик (п.3–4)** SQL будет синтаксически верным, но **бизнес-логически опасным** — ровно то, о чём предупреждает статья Epsilon Metrics.

## A.2. Визуальный дизайн дашбордов и графиков (критично для «продуктового» вида)

| # | Что запросить | Формат | Зачем | Куда в проекте |
|---|---------------|--------|-------|----------------|
| 1 | **Брендбук / UI-kit** | PDF, Figma | Цвета, шрифты, отступы | `viz/style.py`, `PresentationTheme`, Streamlit CSS |
| 2 | **3–5 референс-дашбордов** | скриншоты Power BI / Looker / их BI | Layout, плотность, иерархия | `DashboardLayout`, `presentation_renderer.py` |
| 3 | **Каталог типов графиков** | таблица: сценарий → тип → оси → пример | Правила ChartAgent | `domain/chart_playbook.yaml`, FEW_SHOT_CHART |
| 4 | **Правила KPI-карточек** | какие метрики всегда сверху, формат чисел, Δ% | DashboardAgent KPI | `app/kpi_utils.py`, шаблоны KpiCard |
| 5 | **Требования к подписям** | валюта, округление, тысячи/млн, НДС вкл/искл | format_number_ru, оси | `viz/style.py` |
| 6 | **Мобильность / экспорт** | нужен ли PDF, только desktop | Экспорт PNG/PPTX/PDF | UI actions |
| 7 | **Доступность** | контраст, colorblind | Палитра | сейчас Okabe-Ito — сверить с брендом |
| 8 | **Локализация** | только RU или RU/EN | i18n | UI + промпты |
| 9 | **Шаблон презентации** | .pptx corporate master | Слайды руководству | `PresentationRenderer` |
| 10 | **«Плохие» примеры** | что не нравится | Negative few-shot для ChartAgent | промпты |

**Минимум:** 1 + 3 + 5 + один референс-дашборд (2).

Сейчас стиль **зашит** (gov #003366, Arial, Br). Для продукта нужен **Design Token Layer**: один YAML → `viz/style.py` + Streamlit.

└───────┬───────┘   └───────────────┘   └───────────────────┘
        │
┌───────▼───────────────────────────────────────────────────────┐
│  SEMANTIC LAYER (новое ядро продукта)                           │
│  • schema_registry (таблицы, колонки, FK)                       │
│  • metrics_catalog (бизнес-определения)                         │
│  • chart_playbook (сценарий → тип графика)                      │
│  • dashboard_templates (UC → layout + charts)                     │
│  Без RAG: YAML/JSON + версионирование в git                     │
└───────┬───────────────────────────────────────────────────────┘
        │
┌───────▼───────────────────────────────────────────────────────┐
│  DATA CONNECTOR LAYER                                           │
│  • DuckDB / Postgres / ClickHouse adapter (read-only)           │

└─────────────────────────────────────────────────────────────────┘

**Ключевое решение:** вместо RAG — **явный Semantic Layer в репозитории** (как у dbt metrics / LookML lite). Это масштабируется, тестируется, согласуется с аналитиками заказчика.

# Часть H. Definition of Done «полноценный продукт»

Продукт считаем **готовым к пилоту в контуре заказчика**, когда:

1. **Данные:** read-only подключение к stage-БД, RLS по ролям.
2. **Качество:** ≥ 85% golden questions проходят eval (SQL executes + визуал + инсайты).
3. **Дизайн:** дашборды соответствуют согласованным референсам (структура + бренд).
4. **Сценарии:** топ-5 UC работают end-to-end (вопрос → дашборд/презентация → экспорт).
5. **Эксплуатация:** auth, audit log SQL, мониторинг, документация для админов.

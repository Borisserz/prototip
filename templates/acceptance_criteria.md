# Критерии приёмки ответов системы

**Назначение:** договориться заранее, когда ответ считается **успешным**, а когда — нет.  
**Кто заполняет:** PM + аналитик заказчика + руководство (согласование порогов).  
**Связано с:** [use_case_card.md](use_case_card.md), [PLAN_PRODUKTA.md](../PLAN_PRODUKTA.md) часть H

---

## 1. Уровни проверки

Каждый use case (UC) проверяется по четырём уровням:

| Уровень | Код | Что проверяем |
|---------|-----|---------------|
| **L1 Техника** | `sql_ok` | SQL выполнился без ошибки на sandbox |
| **L2 Данные** | `data_ok` | Цифры совпадают с эталоном в допустимых пределах |
| **L3 Визуал** | `viz_ok` | Тип графика и структура соответствуют playbook / ui_brief |
| **L4 Смысл** | `insight_ok` | Выводы на русском, без жаргона, релевантны вопросу |

**Общий успех UC:** все отмеченные как обязательные уровни пройдены.

## 2. Пороги для пилота (заполнить до старта)

| Метрика | Предложение prototip | Согласовано заказчиком |
|---------|----------------------|------------------------|
| Доля UC с успехом L1–L4 (MVP набор) | ≥ 85% | ___% |
| Макс. время ответа (простой вопрос) | 90 сек | ___ сек |
| Макс. время (дашборд) | 3 мин | ___ мин |
| Макс. время (презентация 5 слайдов) | 10 мин | ___ мин |
| Допуск по числам vs эталон SQL | ±0% (точное совпадение) | ±___% |

---

## 3. Чеклист L1 — SQL

- [ ] Только `SELECT`, без `INSERT/UPDATE/DELETE`
- [ ] Запрос укладывается в timeout (___ сек)
- [ ] Используются только разрешённые таблицы/колонки
- [ ] RLS-фильтры роли применены (если настроены)
- [ ] Результат не пустой (или пустой — осознанно, с пояснением)

---

## 4. Чеклист L2 — Данные

- [ ] Сравнение с **эталонным SQL** аналитика (из `sql_examples.yaml`)
- [ ] Допустимое отклонение: ___%
- [ ] Grain корректен (не задвоение из-за JOIN)
- [ ] Период и фильтры соответствуют вопросу

**При расхождении:** аналитик заказчика фиксирует баг или уточняет эталон.

---

## 5. Чеклист L3 — Визуал

- [ ] Тип графика по [chart_playbook](../domain/chart_playbook.yaml) (line / horizontal_bar / …)
- [ ] Подписи осей на русском
- [ ] Единицы (Br, %, шт.) корректны
- [ ] Структура экрана по [ui_brief](ui_brief.md)
- [ ] Бренд: цвета/шрифты из согласованного tokens (после фазы 3)

**Не требуется на пилоте:** pixel-perfect совпадение с Power BI.

---

## 6. Чеклист L4 — Выводы

- [ ] 3–5 тезисов + ключевой вывод
- [ ] Без выдуманных цифр (только из данных)
- [ ] Термины из glossary заказчика
- [ ] Тон: для руководства / для аналитика (по режиму)

---

## 7. Поведение при ошибке (согласовать)

| Ситуация | Действие системы |
|----------|------------------|
| SQL не выполнился | Показать сообщение + предложить переформулировать / режим аналитика |
| Пустые данные | «Нет данных для отображения», без ложного «успешно» |
| LLM timeout | Повтор / сообщение о перегрузке |
| Подозрительные цифры | ___ (скрыть / показать с дисклеймером / эскалация) |

## 9. Отчёт eval (целевой процесс)

После фазы 4 — автоматический прогон `tests/eval/golden_questions.yaml`:

| Показатель | Формула |
|------------|---------|
| SQL success rate | L1 пройдено / всего вопросов |
| Full success rate | L1–L4 пройдено / всего |
| Среднее время | по логам |

**Пилот считается успешным**, если full success rate ≥ согласованного порога (§2).
